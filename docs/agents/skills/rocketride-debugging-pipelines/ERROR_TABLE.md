# Error → Cause → Fix

**Load this when:** a `validate()` error or a run failure needs diagnosing — every error → cause →
fix in one place.

**Single source of truth for RocketRide errors** (build-time + runtime). The configuring skill's
`PIPELINE_ANTIPATTERNS.md` keeps only a 3-row TL;DR of the commonest build-time errors and points
here for the full list.

The exact error message maps to an exact cause and an owning phase. Quote the real message, find
the row, route the fix.

| Error message | Cause | Owning phase | Fix |
|---|---|---|---|
| `Connection closed` / `Connection timeout` | **event loop blocked** by sync I/O (input(), time.sleep, requests, readFileSync) | running | use async I/O; never block the async loop |
| `Connection closed unexpectedly` | same — blocked event loop | running | same |
| `The service <provider> was not found` | `provider` misspelled / not in catalog | designing | check the node index; fix the name |
| validate error contains `references unknown component id` | a `source`/`input`/`control` entry names a component `id` that doesn't exist | designing | fix the component id in the wiring |
| validate error contains `input has unknown lane` | output lane ≠ input lane on an edge (input names a lane the node doesn't provide) | designing | add a converter or pick compatible nodes |
| `KeyError: '<key>'` | response key ≠ `laneName` | configuring/running | read `result_types`; use defaults or match client code |
| `Pipeline is already running (task <id>). Reuse it (useExisting / use_existing), or stop it and run again.` (on 3.6.0 and earlier: `Pipeline is already running.`) | a second `use()` for the same owner, `project_id` and source: without a custom `token` both runs hash to the same task (a custom token that is already running collides the same way) | running | stop the running one first (`terminate(token)` in the SDKs, or stop the run from the IDE) and run again; or attach to it with `useExisting` / `use_existing=True`; or, to run several instances at once, give each `use()` its own unguessable `tk_` token (SDK `use()` or `rocketride start --token`; the IDE and the MCP `run_pipeline` tool have no token parameter) |
| `No development team selected. Open Account > Profile and choose "Set as development team".` (on 3.6.0 and earlier: `No development team is set — pick one in your profile before running pipelines`) | a development run (IDE, SDK `use()`, `rocketride start`) from an account with no development team; runs are billed to that team, so the server refuses rather than guess | running | open **Account** from the footer of the RocketRide sidebar (IDE or cloud) → **Profile** → **Development team** → **Set as development team** on a team. Teams are listed for the active organization only: for another organization, first open the **Organization** tab → **Organizations / Workspaces** → **Switch to**. Or call `client.account.setDevTeam(teamId)` (`set_dev_team` in Python). No team listed: ask an organization admin to add you to one. Then run again |
| `Pipeline configuration is missing or invalid. ...` (on 3.6.0 and earlier: `'NoneType' object has no attribute 'get'`, or with a `source` given `'NoneType' object does not support item assignment`; for a string or list, `'str'` or `'list'` in place of `'NoneType'`, raised by the plan check on the execute path (SDK `use()`, the IDE's Run, MCP) or by the first read of the pipeline on the launch path (IDE debug session, REST `PUT /task`), where a list with a `source` gave `list indices must be integers or slices, not str`; an empty `{}` pipeline was reported as having no source component, or with a `source` as `Pipeline source component "<id>" not found in components list`; `Missing pipeline configuration in launch request` was never reached) | a run request reached the server with no pipeline, an empty one, or something other than a pipeline object. The SDKs refuse a `use()` with neither `filepath` nor `pipeline`, but they send an empty pipeline: a `.pipe` file that holds `{}` or `{"pipeline": {}}`, or (TypeScript) `use({ pipeline: {} })`. A string or list reaches the server from a `.pipe` file whose JSON is a list or a string (both SDKs pass such a file through unchanged), from an untyped `use(pipeline='./x.pipe')` in JavaScript or Python (the MCP `run_pipeline` tool passes `pipeline` through the same way), or from a hand-built request | running | pass `use()` a `filepath` to a `.pipe` file that defines the pipeline (its components and source), or the pipeline object itself as `pipeline`; if the `.pipe` file is empty, fill it in |
| `Pipeline has no source. ...` (on 3.6.0 and earlier: `Pipeline does not have a source component defined`) | no `source` argument, no top-level `source`, and no component whose config has `"mode": "Source"` (often a source node written with `"config": {}`) | designing | give the source node its full config (`{"hideForm": true, "mode": "Source", "parameters": {}, "type": "<provider>"}`), or set the top-level `source` (or `use()`'s `source`) to the component id to start from |
| `Invalid API key` | wrong/missing key | configuring | set `${ROCKETRIDE_*}` env var correctly |
| run/validate failure mentioning `project_id` (no single verbatim message) | variable used in `project_id` | configuring | use a literal GUID |
| empty / wrong output, no error | wrong wiring or wrong input data | designing/data | trace the first node with empty output; check input + lanes |
| store returns nothing | missing embeddings or different models for ingest and query | configuring/designing | **Pipeline lanes:** embed before the store using the same model for documents and questions. **Agent/app tools:** configure the store's embedding provider and use the collection's model; upstream embedding lanes do not process tool calls |
| `Documents have no embedding vectors. Configure embeddings before writing to the store.` (on 3.6.0 and earlier: `object of type 'NoneType' has no len()`; for a document with neither a vector nor a model name on an existing collection, `You must run your documents through an embedding filter`) | a document on the documents lane has no vector; refused before a new collection or its setup record is written, and on an existing collection. Tool `upsert` is not affected: it takes the vector from the call or computes it, and reports its own errors | configuring/designing | pass the documents lane through an embedding node (`embedding_transformer`, `embedding_openai`, ...) before the store |
| `Question has no embedding vector. Embed questions with the same model as the stored documents.` (on 3.6.0 and earlier: `You must run your question through an embedding filter` for a question with neither a vector nor a model name; with a model name, no error and no documents while the collection did not exist yet, otherwise the driver's own error, such as `To use semantic search, you must bind to an embedding module`) | a semantic question on a pipeline lane has no vector; refused before the driver is called | configuring/designing | embed the questions lane using the same model as the stored documents. Agent-tool `search` computes its vector separately through the store's embedding provider |
| `Documents are missing an embedding model name. ...` (previous wording: `You must run your documents through an embedding filter`) | a document has a vector but no embedding model name; pipeline writes and tool `upsert` share this check | configuring/designing | **Pipeline lanes:** pass documents through an embedding node (`embedding_transformer`, `embedding_openai`, ...) that records both the vector and model name. **Agent/app tools:** configure the store's embedding provider and model name, or supply both `embedding` and `embedding_model` per document to `upsert`; tool calls do not pass through upstream embedding lanes. Match the model used by the collection |
| `The collection uses <model> but the document was encoded with <model>` (an empty first model reads `The collection uses  but the document was encoded with <model>`) | the documents were embedded with another model than the one in the collection's setup record, which holds the model of the collection's first write. An empty first model means a server before this fix (3.6.0 and earlier) created the collection from a first write that had a vector but no model name; no later write can match it | configuring | embed with the collection's model. For an empty first model, choose a new collection or table name; to reuse the name, back up its data, then delete the collection or table so the next write recreates it (deletion loses its data) |
| `Question has no embedding model name. ...` (previous wording: `You must run your question through an embedding filter`) | a question on the pipeline questions lane has a vector but no embedding model name | configuring/designing | pass the questions lane through an embedding node using the same model as the stored documents. For agent-tool `search`, configure the store's embedding provider instead; it computes the query vector itself and reports its own provider errors |
| `Error checking collection: Collection setup record is missing or invalid (found <n>, expected 1). ...`; Elasticsearch: `Index setup record is missing or invalid ...` (previous wording: `Collection does not have control document, found <n>`) | the configured collection, table or index lacks exactly one RocketRide setup record: it may have been created by another tool, damaged, or affected by concurrent creation | configuring | choose a new collection, table or index name. If reusing the name, investigate and back up existing data before deleting/recreating it; deletion loses its data |
| `Vector store connection is unavailable. Check its connection settings and startup errors.` (previous wording: `No document store`) | a pipeline lane received data while the store was not open: initialization failed or data arrived after it closed | running | read the node's earlier startup error, fix its connection settings (host, port, credentials, collection/table), and restart. Tool calls have their own `vectordb tool: store not initialized` guard; check the same startup error there |
| `<Store>: unsupported similarity '<value>'. Set "similarity" to: ...` (previous wording: `The metric you provided in the config.json does not match required <store> configurations`; Astra DB: `The similarity metric you provided in the config.json ...`) | the store node's `similarity` value is not accepted; names and case differ between drivers | configuring | choose an exact value listed in the message. Accepted metrics are unchanged by this wording update; Milvus keeps its existing validation and message |
| agent does nothing / errors on invoke | control plane wrong, or `invoke` min not met | designing | put `control:[{from:<agent>}]` on the controlled node; satisfy invoke min/max |
| `RocketRide cloud database is not available for this task: this server has no RocketRide cloud database ...` | `rocketride_sql` / `rocketride_vector` / `rocketride_graph` on an engine with no database broker (for example, a local or self-hosted engine without the broker env) | designing | run the pipeline on a server with a configured RocketRide database broker, or switch to a node with its own connection settings: `db_postgres` for SQL, PostgreSQL (pgvector), provider `postgres`, for vectors, or `graph_neo4j` for graphs |
| `RocketRide cloud database is not available for this task: this RocketRide Cloud server is missing required database broker configuration ...` | a hosted engine is missing database broker configuration; the server also emits a warning | running | contact the server operator to restore the broker configuration, then retry the pipeline; no database-node replacement is needed |
| `RocketRide cloud database is not available for this task: <broker error>` | the engine's broker call failed: a transient outage, a rejected request (bad broker token, unknown tenant), or a misconfigured broker URL | running | a transient outage: retry; anything else: the operator of that engine checks the broker URL, token and tenant; the broker error after the colon says which it was |
| `ROCKETRIDE_CLIENT_ID is not set` / `Account.resolve_db_dsn returned an empty DSN` (servers before 3.5.0) | the earlier wording of the cloud database failures above: a `rocketride_sql` / `rocketride_vector` / `rocketride_graph` node got no database from its engine | running | 3.5.0 and later report `RocketRide cloud database is not available for this task: ...` instead; follow the matching row above |

## Reading the trace
- Per-node traces are on by default (`pipelineTraceLevel` server default `"summary"`; pass `"full"`
  for more detail). `"none"` still yields chapters/console logs, but the traces come back empty.
- Status fields that tell the story: `state`, `exitCode`, `exitMessage`, `errors[]` (capped at 1000),
  `failedCount`, `completedCount`. The `apaevt_flow` events show `op` (begin/enter/leave/end) per
  pipe with `trace.lane` / `trace.error`.
- Correlate by `projectId` + `source` (begin/end events carry no token).

## Where each cause is fixed
- **Config** (field/key/model) → `rocketride-configuring-pipelines` → re-fetch schema, re-validate.
- **Wiring/lane/control** → `rocketride-designing-pipelines` → re-wire → re-configure → re-validate.
- **Runtime** (loop/use_existing/blocking) → `rocketride-running-pipelines` → fix the run code.
- After **any** fix: `validate()` must be clean again before re-running.
