## What it does

Connects a RocketRide pipeline to [Azure Boards](https://azure.microsoft.com/en-us/products/devops/boards). On start, it authenticates with a Personal Access Token, runs a WIQL query against a project to get matching work item IDs, then fetches full field data via the batch API (200 IDs per call).

Each work item becomes one pipeline entry on the **documents** lane:

- `page_content` is a readable summary — title, type, state, assignee, iteration path, tags, and the description (converted from HTML to plain text).
- Metadata carries the same fields individually for downstream filtering.

This is a **source** node — it pulls from Azure Boards based on its own config rather than reacting to inbound pipeline data, and performs one finite pass per run, capped by **Max Records** (default 200). A failure on one work item is logged and skipped rather than aborting the whole pull; a failure while querying or fetching (network error, or a rate limit that exhausts its retries) is reported as an incomplete run rather than a quiet status line. A `429` is retried with bounded backoff honoring `Retry-After` first.

## Lanes

| Lane out | Description |
| --- | --- |
| `documents` | One document per work item: text summary + structured metadata |

## Authentication

Personal Access Token via HTTP Basic auth with an empty username. Generate one from your Azure DevOps user settings, scoped to Work Items (Read).
