# azure_boards

A RocketRide source node that runs a WIQL query against an Azure DevOps project and emits matching work items into a pipeline as document records.

## What it does

On start, the node authenticates to Azure DevOps with a Personal Access Token (Basic auth, empty username) and runs the configured WIQL query against `POST /{organization}/{project}/_apis/wit/wiql`, which returns matching work item IDs only. It then fetches full field data for those IDs via `POST /{organization}/_apis/wit/workitemsbatch`, chunked at 200 IDs per call (the API's hard batch limit).

Each work item is converted and emitted as one pipeline entry on the **documents** lane:
- `page_content` is a readable summary: title, type, state, assignee, iteration path, tags, and the description (converted from Azure DevOps' HTML format to plain text).
- Metadata carries the same fields individually (`workItemType`, `state`, `assignedTo`, `iterationPath`, `tags`) for downstream filtering.

This is a **source** node (`classType: ["source"]`, `register: "endpoint"`) — like `confluence`/`telegram`/`webhook`, it actively pulls based on its own config rather than reacting to an inbound entry. It performs one finite pass per pipeline run, capped by **Max Records** (default 200), rather than listening indefinitely.

Failures are isolated per work item: if one fails to convert or emit, it's logged and skipped, and the pull continues with the rest of the results. A failure while querying or fetching (network error, or a rate limit that exhausts its retries) is different — work items already emitted stay emitted, but the sweep itself is incomplete, so that's reported as a failed run rather than a quiet status line.

A `429` response is retried with bounded backoff honoring the `Retry-After` header before it's treated as a failure.

## Configuration

### Lanes

| Lane out | Description |
|---|---|
| `documents` | One document per work item: readable text summary + structured metadata |

### Fields

| Field | Type | Description |
|---|---|---|
| `organization` | string | Azure DevOps organization name |
| `project` | string | Project to query work items from |
| `personalAccessToken` | string | Azure DevOps PAT with Work Items (Read) scope |
| `wiql` | string | Work Item Query Language query; must select `[System.Id]` |
| `maxRecords` | number | Hard cap on total work items pulled in one run (default 200) |

---

## Authentication

Personal Access Token via HTTP Basic auth with an empty username — the standard Azure DevOps PAT convention. Generate one from your Azure DevOps user settings (`Personal access tokens`), scoped to Work Items (Read).
