# tool_linear

A RocketRide tool node that gives an agent access to a Linear workspace: search and read issues, and optionally create, comment on and update them. Pick it when a triage, support or standup pipeline needs to read or file Linear issues without hand-writing GraphQL.

## About Linear

Linear is an issue tracker for software teams. Work is organised into teams, each with a short key (such as `ENG`) and its own workflow states, and every issue gets an identifier like `ENG-123`. Linear exposes a documented GraphQL API and has a free plan.

## What it does

The node has no data lanes; it exists only as an agent tool server, exposing eight operations over Linear's GraphQL API. An agent typically lists teams or states, searches for issues, reads one with its recent comments, and, when writes are enabled, files an issue, comments on it or moves it between states. Pick it over a generic HTTP tool when you want Linear's pagination, rate-limit handling and team scoping done for you.

## As a tool

The server-name prefix is `linear`, producing these registered functions.

| Function | Description |
|---|---|
| `linear_check_connection` | Verify the API key and return the authenticated user. |
| `linear_teams_list` | List teams (id, key, name), limited to the configured allowlist. |
| `linear_issues_search` | Search issues by team, state name, assignee (name or `me`) and title text, newest-updated first, with cursor paging. |
| `linear_issue_get` | Return one issue by identifier (`ENG-123`) or id, with its description and recent comments. |
| `linear_states_list` | List a team's workflow states (id, name, type). |
| `linear_issue_create` | Create an issue (write). |
| `linear_comment_add` | Add a markdown comment to an issue (write). |
| `linear_issue_update` | Update an issue's title, description, priority, state or assignee (write). |

Every function returns `success`, plus its own fields on success and `error` on failure. Linear failures are returned in that envelope rather than raised. `linear_issues_search` accepts `team_key`, `state`, `assignee`, `text`, `first` (1–100) and `after`, and returns `issues`, `end_cursor` and `has_next_page`; pass `end_cursor` back as `after` to continue. Priorities are integers: 0 none, 1 urgent, 2 high, 3 medium, 4 low. State arguments are state names, resolved to ids per team.

## Configuration

### API Key

A Linear personal API key, stored encrypted and masked in the UI. Leave it empty only if you set `ROCKETRIDE_LINEAR_API_KEY` on the engine host; the config field wins when both are present, and startup fails when neither yields a value.

### Read only

On by default. While on, `linear_issue_create`, `linear_comment_add` and `linear_issue_update` refuse and name this field in the error.

### Teams

Comma-separated team keys the node may touch, for example `ENG,OPS`. Empty means every team. The list is added to every issue filter, and tools that act on a single issue check the issue's team after fetching it, so an identifier from another team is refused.

### Max results

Default page size for issue searches, clamped to 1–100.

## Authentication

Create a personal API key under Settings → Account → Security & access in Linear. The key is sent raw in the `Authorization` header, without a `Bearer` prefix. OAuth is not supported.

## Notes

### Experimental

The node is marked `experimental`. Its request and response shapes are read from Linear's developer documentation, but it has not been run against a live workspace, so the surface may change.

### Rate limits

Linear limits each API key to 2,500 requests and 3,000,000 complexity points per hour. A limited request comes back as HTTP 400 with code `RATELIMITED` rather than 429; the node returns `success: false` with the reset time instead of raising. The client also pauses (up to 30 seconds) until the reset when fewer than 50 requests remain. Queries request one level of nesting only.

### Retries and duplicate writes

Reads time out after 30 seconds and retry twice with exponential backoff on connection errors and 5xx responses. The three write functions are never retried, because Linear offers no idempotency key and a retry could duplicate an issue or comment.

### Limits

Titles, descriptions and comments over 32 KB are rejected rather than truncated. There is no delete, archive, project, cycle or user-administration operation.
