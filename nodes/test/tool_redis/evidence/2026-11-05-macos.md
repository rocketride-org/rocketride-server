## Reproduction

Use the fixture and engine setup in [the test README](../README.md), then run
from `nodes/`:

```sh
../dist/server/engine -m pytest test/tool_redis test/memory_persistent test/test_contracts.py -q --rootdir .
../dist/server/engine -m pytest test/test_dynamic.py -k tool_redis -q --rootdir .
```

Set all three `REDIS_*_TEST_URL` variables, the test CA path and
`ROCKETRIDE_REDIS_HOST` as documented. Missing live fixture variables cause
skips and do not establish live verification. The generic Redis case now
selects fixture port 6381 explicitly in its test configuration. Previously
it ignored the unlisted `ROCKETRIDE_REDIS_PORT` variable and connected to
6379, which failed when using the supplied fixtures. A pipeline-builder
regression test covers the correction.

## Follow-up implementation review

A review against RocketRide's v1 feedback started from `984a3d8825451039aea54f75e634f6eb1dc4f37f`.
Regression tests reproduced the following issues before their fixes:

- Malformed SCAN arguments were normalized into an empty dictionary and
  could execute a default scan. Non-object inputs and failed argument-model
  conversions now return a sanitized `invalid_input` without contacting Redis.
  Empty object, JSON-object, envelope and Pydantic inputs remain supported.
- `rediss://host:0` silently selected the default port. Explicit URL ports
  now pass the same 1–65535 validation as the separate port field.
- The hosted TLS connection's peer check ran after redis-py had sent the
  TLS handshake. Connections now pin validated numeric destinations, check
  the TCP peer, then restore the original hostname for verified TLS/SNI.
  Reconnects resolve and validate again. Address fallback occurs before
  commands, and no command retry or insecure TLS switch was added.

The INCR tool description also warns that each successful invocation changes
state again and recommends GET for inspection. This is guidance, not proof
that the earlier agent/model repeat issue is resolved. The duplicate manual
catalog link was removed from the node architecture guide, which explicitly
requires the generated catalog rather than hand-maintained node lists.
