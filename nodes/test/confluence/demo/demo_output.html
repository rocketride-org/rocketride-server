Deploy Runbook

Source: Confluence page “Deploy Runbook”

text lane

This runbook describes how to deploy the checkout service to production. Follow every step in order and do not skip the smoke test at the end.

Pre-deploy checklist
Before starting a deploy, confirm the on-call engineer has acknowledged the release window and that the previous deploy's canary has been running cleanly for at least two hours. Check the dashboard for error rate and latency regressions before proceeding.

Deploy steps
Cut a release branch from main, tag it with the current date, and push the tag. The CI pipeline builds the image automatically once the tag lands. Wait for the build to go green, then promote the image to the staging cluster first. Run the staging smoke tests, and only promote to production once staging has been stable for fifteen minutes.

Rollback
If the smoke test fails, immediately revert the production deploy to the previous tag and notify the incident channel. Do not attempt to patch forward during a rollback situation.

Incident Response checklist

Source: Confluence page “Incident Response checklist”

text lane

Use this checklist during any production incident classified as SEV-1 or SEV-2. The goal is to restore service quickly and capture enough detail for a clean postmortem.

First five minutes
Declare the incident in the incident channel, assign an incident commander, and start a timeline document. The incident commander is responsible for coordination only and should not personally debug the issue unless no one else is available.

Communication
Post an update every fifteen minutes during a SEV-1, even if the update is “still investigating.” Silence during an active incident causes more anxiety than a lack of progress.

After the incident
Once service is restored, schedule a postmortem within two business days while details are still fresh. The postmortem should focus on process and system gaps, not on assigning blame to an individual.
