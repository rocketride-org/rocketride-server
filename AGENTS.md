# AGENTS.md

Contributor guide for agents working in this repository.

## Co-located documentation rule

Documentation is co-located with the code it documents and is gathered into the
docs site by `builder docs:build`. When a change alters a public contract, update
the corresponding co-located doc in the SAME change:

- General product docs (quickstart, concepts, integrations, examples, evaluate,
  glossary, troubleshooting, cloud, self-hosting) -> `docs/product/`.
- A public TypeScript SDK signature -> `docs/clients/typescript/` (guides). Generated
  reference under `packages/client-typescript/docs/reference/` (do not edit;
  regenerated by `client-typescript:docs-generate`).
- A public Python SDK signature -> `docs/clients/python/` (reference generated).
- The MCP protocol surface -> `docs/mcp/`.
- The WebSocket (5565) / engine protocol surface -> `docs/internal/engine-protocol/`.
- The VS Code extension surface -> `docs/clients/vscode/`.
- Contributor/internal docs (builder, engine internals, node schema/testing, n8n,
  pre-commit hooks) -> `docs/internal/`.
- Agent-facing docs (`ROCKETRIDE_*`) -> `docs/agents/` (exported to `.rocketride/docs/`
  by `./builder docs:export`).
- Node docs stay co-located: `nodes/src/nodes/<name>/README.md` (generated params
  between markers, unchanged rule).
- Package READMEs are GENERATED committed copies: edit `docs/clients/<name>/readme.md`
  or `docs/mcp/readme.md`, then run `./builder docs:export`; never edit
  `packages/client-*/README.md` directly. CI runs `./builder docs:check` to catch
  drift. The VS Code marketplace readme source is `docs/clients/vscode/readme.md`
  (copied at package time).

Prose-only edits and internal refactors that do not change a public contract do not
require doc updates. Treat the doc as part of the change, not a follow-up. Do not create
a separate docs repo or a top-level docs site folder. Verify with `builder docs:build`
and `builder docs:check`.
