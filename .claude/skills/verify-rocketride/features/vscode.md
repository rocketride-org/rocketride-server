# VS Code extension

The RocketRide extension (`apps/vscode`) adds a RocketRide view to the activity bar, a status bar item, a Welcome page, a Settings page, and editors for `.pipe` and `.rrapp` files. A user connects it to an engine, then builds and runs pipelines and apps from the workspace. On connect it writes the engine's address and key into the workspace `.env` for the SDKs and CLIs. The canvas, run, and chat flows are in [vscode-canvas.md](./vscode-canvas.md).

## Sub-features

- `vscode-launch` starts VS Code with this checkout's extension in a private profile, and the extension activates.
- `vscode-connect` connects from the Welcome page with Direct Connect, the run's host URL, and its API key. The status bar shows `RocketRide: Connected (Direct)`, and the RocketRide view shows the Apps, Nodes, and Pipelines tabs.
- `vscode-env` writes `ROCKETRIDE_URI` and `ROCKETRIDE_APIKEY` for the connected engine into the workspace `.env`, and keeps the user's own variables when it rewrites the file.
- `vscode-sidebar` lists the workspace's `.pipe` files in the Pipelines tab, follows files created and deleted outside VS Code, and asks before it changes a file whose `project_id` duplicates another. It fills in a missing `project_id`, and reformats the file, without asking; that is intended.
- `vscode-commands` opens the Settings page, the Server Monitor, and the Welcome page from the Command Palette.
- `vscode-app-builder` creates an app with **New app** and opens it in the App Builder.

## How to get to it (user POV)

- Install the extension from the Marketplace or a `.vsix`, or press F5 in `apps/vscode` to run it from source. A first start opens **Welcome to RocketRide**.
- Pick a connection mode on the Welcome page or in **RocketRide: Settings**: Local (the extension downloads and starts an engine), Direct Connect (a host URL and API key), Docker, Service, or RocketRide Cloud.
- Click the RocketRide icon in the activity bar for the Apps, Nodes, and Pipelines tabs, **Monitor**, and the footer menu.
- Run commands from the Command Palette (F1). Connect, Disconnect, and Reconnect are hidden there; they are in the sidebar footer menu.
- Local, Docker, Service, and Cloud modes are not driven here: Local and Service download an engine from GitHub releases, Docker needs a Docker daemon, and Cloud needs a RocketRide account.

## Driving it with rr-verify

Preconditions:

- Your run was launched with `--mock`, and `rr-verify doctor` exits 0 with the line `ok   the VS Code extension build is newer than its source`. A `WARN` line names the build to run.
- `build/vscode` exists. Build it once with `./builder vscode:build`.
- Each command below records PNGs, a `.webm` video, and a JSON record under `.verify/<run-id>/<feature-id>/` and ends with `PASS: <step>` or `FAIL: <step>: <failed checks>`. Exit code 0 means every check passed, 1 means one failed, and 2 means the step could not run, such as VS Code not running.

- **Start VS Code.** Run `rr-verify vscode launch`. The first time it downloads VS Code into `.verify/vscode-cache` and unpacks any missing system libraries there. It prints `vscode:    1.143.1, pid <pid>, devtools port <port>, ready in <n>s`, `extension: RocketRide extension activated successfully`, `status:    RocketRide: Setup`, and the workspace path, `.verify/<run-id>/vscode-profile/workspace`. The workspace holds `pipelines/quickstart-chat.pipe` and `pipelines/quickstart-chat-no-return.pipe`. Then run `rr-verify vscode shot --label vscode-launch launched` to record the Welcome page; it ends with `PASS: shot-launched`.
- **Connect.** Run `rr-verify vscode connect`. It chooses **Direct Connect** on the Welcome page, enters `$ROCKETRIDE_URI` and `$ROCKETRIDE_APIKEY`, clicks **Test connection**, then **Save & Connect**, and opens the RocketRide view. Every line starts with `ok`, including `Test connection succeeds: Connection successful!`, `Save & Connect connects: status bar: RocketRide: Connected (Direct)`, `the RocketRide sidebar shows Apps, Nodes, and Pipelines: APPS, NODES, PIPELINES`, and `the workspace .env points at this engine: ROCKETRIDE_URI=http://127.0.0.1:<port>`. It ends with `PASS: connect`.
- **Read the .env.** Run `rr-verify record vscode-env -- cat .verify/$RR_VERIFY_ID/vscode-profile/workspace/.env`. It prints a `# RocketRide development connection (managed)` comment, `ROCKETRIDE_URI=` with the run's URI, and `ROCKETRIDE_APIKEY=verify-key`.
- **Keep the user's variables.** Add your own lines: `printf '\n# my own settings\nROCKETRIDE_OPENAI_KEY=sk-user-test\n' >> .verify/$RR_VERIFY_ID/vscode-profile/workspace/.env`. Reopen VS Code with `rr-verify vscode close && rr-verify vscode launch`. It reconnects on its own and prints `status:    RocketRide: Connected (Direct)`. Run `rr-verify record vscode-env -- cat .verify/$RR_VERIFY_ID/vscode-profile/workspace/.env` again. The managed lines are unchanged, and `# my own settings` and `ROCKETRIDE_OPENAI_KEY=sk-user-test` are still there. A `# RocketRide deployment target (managed)` block with `ROCKETRIDE_DEPLOY_URI` and `ROCKETRIDE_DEPLOY_APIKEY` set to the same engine may also appear.
- **List pipelines.** Run `rr-verify vscode pipes --expect quickstart-chat`. It opens the Pipelines tab, expands `pipelines`, and prints `ok   the Pipelines tab lists the workspace pipelines: pipelines/quickstart-chat-no-return.pipe, pipelines/quickstart-chat.pipe` and `ok   pipelines/quickstart-chat.pipe is listed: listed`.
- **Copy a pipeline outside VS Code.** Record the hash with `rr-verify record vscode-sidebar -- sha256sum .verify/$RR_VERIFY_ID/vscode-profile/workspace/pipelines/quickstart-chat.pipe`. Copy it with `cp .verify/$RR_VERIFY_ID/vscode-profile/workspace/pipelines/quickstart-chat.pipe .verify/$RR_VERIFY_ID/vscode-profile/workspace/pipelines/copied.pipe`, wait 3 seconds, and run `rr-verify vscode pipes --expect copied`. It lists `pipelines/copied.pipe` and prints `notification (warning): pipelines/copied.pipe has the same project_id as pipelines/quickstart-chat.pipe. Pipelines with the same id cannot be told apart when they run. The file was not changed.` Run `rr-verify record vscode-sidebar -- sha256sum .verify/$RR_VERIFY_ID/vscode-profile/workspace/pipelines/copied.pipe`. Its hash equals the original's: the extension did not rewrite the copy.
- **Replace a pipeline the way git checkout does.** Run `cp .verify/$RR_VERIFY_ID/vscode-profile/workspace/pipelines/quickstart-chat-no-return.pipe /tmp/rr-verify-$RR_VERIFY_ID-nr.pipe && rm .verify/$RR_VERIFY_ID/vscode-profile/workspace/pipelines/quickstart-chat-no-return.pipe && cp /tmp/rr-verify-$RR_VERIFY_ID-nr.pipe .verify/$RR_VERIFY_ID/vscode-profile/workspace/pipelines/quickstart-chat-no-return.pipe`, wait 3 seconds, and run `rr-verify record vscode-sidebar -- sha256sum .verify/$RR_VERIFY_ID/vscode-profile/workspace/pipelines/quickstart-chat-no-return.pipe /tmp/rr-verify-$RR_VERIFY_ID-nr.pipe`. The two hashes are equal.
- **Delete a pipeline outside VS Code.** Run `rm .verify/$RR_VERIFY_ID/vscode-profile/workspace/pipelines/copied.pipe`, wait 3 seconds, and run `rr-verify vscode pipes --absent copied`. It prints `ok   pipelines/copied.pipe is not listed: not listed`.
- **Run commands.** Run `rr-verify vscode command "RocketRide: Settings" --expect "RocketRide Settings"`, `rr-verify vscode command "RocketRide: Server Monitor" --expect "Server Monitor"`, and `rr-verify vscode command "RocketRide: Welcome" --expect "Get Started"`. Each prints `ok   run "<title>" from the Command Palette: ran` and `ok   the window shows "<text>"`, then `PASS: command`. The Server Monitor screenshot shows the connections and tasks of the run's engine.
- **Create an app.** Run `rr-verify vscode app verifyapp --display "Verify App"`. It clicks **New app** in the Apps tab, fills **App name** and **Display name**, and clicks **Create App**. It prints `ok   Create App opens the App Builder: tabs: DASHBOARD, DESIGN, PACKAGE, STORE, DEPLOY`, `ok   the app folder and its .rrapp file exist: apps/verifyapp-ui/verifyapp.rrapp`, and `ok   the sidebar Apps tab lists the new app: Verify App`. Each app name works once per run, because the folder must not exist.
- **Check your own change.** Write steps to `/tmp/rr-verify-$RR_VERIFY_ID-<name>.mjs` as `export default async ({ page, frame, shot, check, fail }) => { ... }` and run `rr-verify vscode script --label <feature-id> /tmp/rr-verify-$RR_VERIFY_ID-<name>.mjs`. `frame(selector)` returns the visible webview whose page matches the selector, `check(label, fn)` records one check, and `page` is the VS Code window. Copy the closest step from `bin/vscode.mjs`.
- **Close VS Code.** Run `rr-verify vscode close`. It prints `stopped VS Code pid <pid> and its process group`. `rr-verify stop` also closes it.

## Gotchas

- **How VS Code runs without a display.** `launch` starts the VS Code build with `--ozone-platform=headless` and `--ozone-override-screen-size=1440,900`, so Chromium renders without X11, Wayland, or Xvfb, and screenshots and video come from the DevTools protocol. Without `--ozone-override-screen-size` the window is 400x270 pixels. Xvfb was not needed and was not tried.
- **Libraries come from apt-get download.** The VS Code build links against `libgtk-3`, `libcups`, `libcairo`, and `libpango`. On this Ubuntu 24.04 server they were missing, and VS Code exited with `error while loading shared libraries: libcups.so.2`. `launch` downloads those packages and their missing library dependencies with `apt-get download`, unpacks them with `dpkg -x` into `.verify/vscode-cache/sysroot`, and sets `LD_LIBRARY_PATH`. No root is needed. If `ldd` still reports a missing library afterwards, `launch` fails and names it.
- **The sandbox needs `--no-sandbox`.** Without it, VS Code aborts with `The SUID sandbox helper binary was found, but is not configured correctly`, because `chrome-sandbox` must be owned by root with mode 4755.
- **Nothing outside the run is written, except Playwright's shared browser cache.** `launch` installs Playwright's ffmpeg into `~/.cache/ms-playwright` (or `PLAYWRIGHT_BROWSERS_PATH`) when it is missing, because recording needs it, the same cache the browser recipes use. Without a private home, VS Code creates `~/.vscode/argv.json`, `~/.vscode-shared`, `~/.copilot`, and `~/.cache/Microsoft/DeveloperTools/deviceid` even with `--user-data-dir`, and the extension's Local mode installs into `~/.config/RocketRide`. `launch` gives VS Code a private `HOME` under `.verify/<run-id>/vscode-profile/home` and a short `XDG_RUNTIME_DIR` in `/tmp`, because VS Code's IPC socket path fails to bind (`listen EINVAL`) when it is longer than 107 characters. `close` removes the `/tmp` folder.
- **The extension fetches from port 5565 before it is configured.** In a fresh profile in Local mode, the extension downloads `/client/shell` and `/client/typescript` from `http://localhost:5565` at startup, whatever answers there. `launch` writes `rocketride.development.connectionMode` and `rocketride.development.hostUrl` into the profile's settings first, so it fetches from the run's engine instead.
- **The API key lives in VS Code's secret storage**, not in settings, so only the Welcome or Settings page can set it. `--password-store=basic` keeps it in the run's user data. After `connect`, a relaunch of the same run reconnects without the Welcome page.
- **Webviews are nested frames, and hidden editors keep theirs.** Every RocketRide page is a webview: an `iframe.webview` in the window with the page in a nested frame. Two open `.pipe` editors both have a canvas in the page, so the steps act on the visible one. In a `script`, use `frame(selector)` rather than `page.frames()`.
- **The Command Palette hides most RocketRide commands.** `apps/vscode/package.json` hides Connect, Disconnect, Reconnect, Create New Pipeline, Run, Stop, Open App Builder, and others with `when: false`; users reach them from the sidebar, the canvas, or the status bar. `RocketRide: Settings`, `RocketRide: Server Monitor`, and `RocketRide: Welcome` are in the palette, and `rr-verify vscode command` fails with `the Command Palette has no command` for a hidden one.
- **GitHub rate limits show up as errors.** The Welcome and Settings pages fetch engine releases from `api.github.com`. When the address is rate-limited, the record's `errors` holds `GET /repos/rocketride-org/rocketride-server/releases?per_page=100 - 403` and `All version fetch attempts failed`. That is not caused by your change.
- **`errors` in the JSON is broad.** It holds `[error]` lines from the extension host log, error lines from the RocketRide output channel, console errors from every webview, and error notifications, all from the time of the step. Read them before calling a step clean, and compare with the same step on a run of the base branch when in doubt.
- **New app installs packages.** The App Builder runs `pnpm install` in the workspace in the background. The pnpm store is shared in `.verify/vscode-cache/pnpm-store`, so only the first app downloads packages.
- **MCP and the engine's port.** The extension never calls the engine's `/mcp` endpoint, so the `--port 0` problem in [mcp.md](./mcp.md) does not show in VS Code itself. Local mode starts its engine with `--port=0` and without `ROCKETRIDE_URI`, so an MCP client pointed at that engine's `/mcp` would hit it. See the MCP gotchas.
- **External writers can collide with the starter pipeline.** A `.pipe` file that stays empty for more than 500 ms gets the starter pipeline written into it in place, so a writer that pauses before writing (or appends with `>>`) can leave trailing skeleton bytes and invalid JSON. Empty `.pipe` files copied in together with `cp -r` are sometimes never given the starter pipeline, with nothing logged. Both are pre-existing (confirmed 2026-10-27). Write a whole file at once when a recipe needs one.
