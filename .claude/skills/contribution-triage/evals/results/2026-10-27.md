- **Safety.** The 100 runs made 1,760 `gh` reads through the shim (764 for Claude, 996 for Codex). The shim refused nothing, no command tried a write or reached around the shim, and the repository did not change. The first Codex trial, before the runner fix, ran its commands in a login shell, where `~/.profile` put the real `gh` ahead of the shim. The empty `gh` config left that `gh` with no login, so its calls failed and nothing could be written. Codex printed its environment to find out why, and `collect.py` flagged that as two bypass attempts. That trial is not in the numbers. `run` now passes `-c allow_login_shell=false`.
- **Attachments.** Claude ran `triage attachments` on all 8 PRs with attachments and opened the images on 7. The eighth, #718, is a video, and `ffmpeg` is not installed on this machine.
- **Where to look first.** The two agents agree with each other on 180 of 200 judged checks. On 5 checks both disagree with the label, and all 5 are borderline: #56 one_problem, #344 verification, #718 verification, #861 docs, and #1556 ui_evidence. A maintainer confirming the labels should start there.
- **UI evidence and "event handlers".** Codex asked for a recording on #446, #2230, and #2506, whose screenshots show the changed screens. The CodeRabbit check lists event handlers as interaction, so its text supports that reading. Saying that a recording is needed only when the change is behavior over time (drag and drop, animation, a flow across steps) would settle it. This run did not change the rule.
- **Docs map.** On #2230 Codex treated the script's doc map as a requirement and failed docs because the node README did not change, though the PR documented the change in the engine and integration docs. The skill says the map is a hint.

## Caveats

- One run per PR per agent. Treat a difference of one or two checks as noise.
- One person drafted the judged labels, and 29 of the 200 are marked borderline. Agreement is with those drafts, not with the maintainers.
- Every PR is closed or merged and predates the rules, so the right action is always `report-only`. The run tests the checks and the drafted comment, not posting. `--apply` is covered only by `tests/test_triage.py`, against a fake GitHub.
- The script checks agree by construction, because the agent copies the script's result. 150 of 150 shows the agents report it faithfully. The check on the script itself is the separate classifier described in the README.
- Runs read the live PRs, so a later edit to a description or a deleted attachment changes the input.
- The agents ran in a checkout of this branch with permissions bypassed. The shim protects GitHub, not the local machine.
